# 前端展示方案

> 2026-11-01，洛杉矶时间。前提沿用上一轮：WeUI CSS + `devices.css` 的外框 + 原生动画，文件放进仓库，只用系统字体。
> 三个骨架都能直接打开：`设计预览/方向A.html`、`方向B.html`、`方向C.html`。截图在 `设计预览/截图/`。内容都是占位。

## 结论

**推荐方向 A：普通滚动的三段长页，夜蓝底配琥珀色。第一屏就是两台手机和中间的「平台规则」，打开后自动演示一遍。**

理由有四条：

1. **面试官不用学就会看。** 打开就在动，往下滚就是方案和过程，顶栏三个入口一直可见。
2. **内容可以随便往里填。** 长页不怕变长；方向 B 的固定舞台内容一多就要在章节内部滚动。
3. **最贴题。** 第二段第一眼就是「发单端 / 平台规则 / 接单端」的流程表，每行能跳回演示。这正是题面优先要看的产品结构。
4. **外层和微信差别最大。** 深色底上，手机的白屏和绿按钮最像一个真实产品。

配色和结构是分开的，都写在 CSS 变量里。如果本人更喜欢 B 的灰或 C 的蓝，可以把配色换到 A 的结构上，不用重做。

**中间一栏是这次设计的核心想法：** 它不只是说明文字，而是产品结构里的「平台」。任务卡从左手机飞出，在中间那条线上停一下，亮起「校验通过」，再落到右手机。「主打信任」这个判断（CLAUDE.md 判断记录第 3 条，还在待本人确认）就这样用动作讲出来了。

## 1. 三部分怎么衔接

| 问题 | 建议 |
|---|---|
| 观看路径 | 普通滚动：演示 → 方案 → 过程。不劫持滚动，顶栏三个入口可直接跳 |
| 第一屏看到什么 | 左右两台手机，中间一句话标题、平台规则、5 个步骤。不放封面，不放「向下滚动」 |
| 怎么连起来 | 方案表每行有「看演示」，跳回第一屏对应步骤；过程区讲的是这个产品怎么做出来的 |
| 面试官只看一分钟 | 约 16 秒看完一轮演示，再扫一眼方案表和泳道，三段都看到了 |

**自动演示和手动操作共用同一个状态，只有一条规则：一碰就交给人。**

- 打开 1.6 秒后开始，每步停 3.2 秒，走完一轮约 16 秒，停在结果页，不循环。循环会让人读不完，也会抢注意力。
- 点手机里的按钮、步骤或「下一步」，就停止自动，状态显示「手动操作中」，之后不再自己动。
- 想再看一遍点「重播」。

## 2. 怎么有审美

**先定不做什么。** 紫色渐变、卡片墙、emoji 当图标是第一层默认。只说「别用紫」时，模型还容易落到第二层默认：奶油底配衬线和赤陶色，或者近黑底配荧光绿（[这篇文章](https://prg.sh/ramblings/Why-Your-AI-Keeps-Building-the-Same-Purple-Gradient-Website)的观点，只看到搜索摘要，原文没读）。现在的占位页 `index.html` 是奶油底加深绿，正好靠近第二层，完整版不要沿用。

| | A 夜班调度台（推荐） | B 产品说明书 | C 校园招贴 |
|---|---|---|---|
| 底色 | 夜蓝 `#0d1a2b` + 冷灰纸面 `#e4e8ee` | 水泥灰 `#c6c9c4` | 钴蓝 `#1537d6` + 白 |
| 强调色 | 琥珀 `#ffb020` | 信号橙红 `#e8400c` | 亮黄 `#ffe500` |
| 气质 | 冷静，像调度系统 | 工业产品手册，最有个性 | 大字海报，最抢眼 |
| 风险 | 深色页面见得多，靠琥珀和纸面区分 | 灰底在差屏幕上偏闷 | 蓝色面积大，看久了累，方案区必须切白 |

**三个方向共用的规矩：**

- **字体：** 只用系统字体，中文 `PingFang SC` / `Microsoft YaHei`，时间和编号用等宽字体。不用衬线，因为 Windows 上回退到宋体，粗体很难看。
- **层次：** 靠字号、细线和留白分层，不用卡片、阴影和渐变。唯一带阴影的外层元素是飞行中的任务卡。
- **颜色：** 外层不出现微信绿，绿色只留给手机屏幕里面。
- **动效：** 只有表达因果的东西才动。

| 动作 | 时长 |
|---|---|
| 飞卡（起飞 42%，停在平台 20%，落地 38%） | 1300 ms |
| 手机内切页 | 320 ms |
| 半屏弹层滑入 | 340 ms |
| 确认提示 | 1400 ms |
| B 的手机换位 | 550 ms |

不做滚动淡入、视差、发光。

**参考实例：**

| 实例 | 借鉴什么 | 不借鉴什么 | 怎么看的 |
|---|---|---|---|
| [Teenage Engineering OP-XY](https://teenage.engineering/products/op-xy) | 产品当实物摆在纯色背景上，旁边只有极小的标注文字。对应 B 的「A 发单端」小标签 | 整页黑场和大量滚动动画 | 打开看过 |
| [Linear Method](https://linear.app/method) | 超大标题配一行极小的眉题，正文克制。对应方案区的版式 | 它的衬线大标题，中文系统字体做不出来 | 打开看过 |
| [Stripe Checkout](https://stripe.com/payments/checkout) | 第一屏直接放正在运行的产品，并给「体验演示」入口 | 它也用紫色渐变，只借结构 | 打开看过 |
| [Bartosz Ciechanowski：GPS](https://ciechanow.ski/gps/) | 演示嵌在阅读流里，不靠滚动驱动；正文链接能跳到预设状态。对应方案表的「看演示」 | 长文体量 | 读了文本，没看视觉 |
| [Honeycomb Agent Timeline](https://www.honeycomb.io/platform/agent-timeline) | 横向泳道看并行和交接，点开看详情，失败用红色标出。对应「打断」那个红点 | 它面向工程师的指标密度 | 读了产品页文字，没用过产品 |
| [Perfetto UI](https://perfetto.dev/docs/visualization/perfetto-ui) | 选中后详情在下方抽屉显示，时间轴不被遮挡 | 缩放和键盘操作，面试官用不上 | 读了文档 |

## 3. 「我是怎么做的」怎么呈现

| 形式 | 能一眼看懂并行吗 | 能看出判断力吗 | 用法 |
|---|---|---|---|
| 单线时间线 | 不能 | 一般 | 不用，把并行压成了先后 |
| **窗口泳道（推荐做主体）** | 能，几条线同时走 | 配合红点可以 | A、B 用这个，看图即懂 |
| 对话回放 | 不能 | 最好，能看到原话 | 不单独做主体，放进泳道的详情区；C 做了完整版供对比 |
| 纯文字原则列表 | 不能 | 空泛 | 只做筛选入口 |

**推荐的画法（A 已做，用的是真实记录）：**

- **横轴是真实时间，每条泳道是一个窗口。** 条形表示窗口在运行，圆点是一次指令或交付，竖线表示指令落到哪个窗口。
- **一个红点讲最好的故事：** 约 16:36 发现调研派给了子 agent，立刻打断，改开窗口。「子 agent × 3」那条泳道上只有一小段红色。
- **面试官能点三样东西：**
  1. 点圆点，下方显示「本人的判断 / AI 做了什么 / 结果 / 来源」。
  2. 点 5 条工作原则，其余圆点变暗，只留相关事件。
  3. 点「回放过程」，指针沿时间轴走，依次亮起。
- **第一次看到时默认选中那个红点，** 这样不点也能看到一个完整故事。

**之后填内容时要注意：**

- 目前记录只跨 16 分钟，点挤在 16:36 附近。时间拉长后可能要用断轴，或者只保留选中的事件。
- 「列点子」「再去做其他」两条原则目前没有对应记录，骨架里点它们会全部变暗。这是如实反映，等有记录再连。
- 事件和原则的对应是我暂定的，要本人确认。
- 约 16:44 那条的时间是按前后记录推算的，文件里已标注。

## 4. 尺寸和设备

**笔记本：**

- 手机外框改矮：800 px 高（真机比例是 868），屏幕 762。多留出 8% 高度，字因此大一点，肉眼几乎看不出比例变化。
- 用一段小脚本按窗口计算缩放比例：`s = min(1, 可用高度 / 800, 可用宽度 / 428)`，设下限，放不下时页面可以滚动。
- 手机固定宽度，中间一栏吃掉剩余宽度。

实测结果（A 的中间栏内容也都没有超出）：

| 窗口 | A 缩放 | 手机在窗口里的上下范围 | 手机里 16 px 字实际显示 |
|---|---|---|---|
| 1440×900 | 1.00 | 73–873 | 16 px |
| 1280×720 | 0.82 | 55–711 | 13 px |
| 1366×650（估算的 Windows 小本可视高度） | 0.73 | 55–641 | 12 px |

B 和 C 没有顶栏，同尺寸下缩放更大（1280×720 分别是 0.845、0.855）。三个方向在这三个尺寸下都放得下，没有横向滚动。

**手机打开：**

- 宽度小于 900 px 时切成单屏，只显示一台，去掉外框，避免「手机里套手机」。
- 顶部有「发单端 / 接单端」切换。发布时卡片滑出，自动切到接单端，卡片再滑入。
- A 的泳道改成竖向事件列表。
- 三个方向在 390×844 模拟下都没有横向滚动。

## 5. 方向对比

| | A 滚动长页 | B 固定舞台 + 章节 | C 钉住手机 + 滚动推进 |
|---|---|---|---|
| 第一屏会动吗 | 会，自动演示 | 会，自动演示 | 不会，要滚动或点「自动播放」 |
| 到达方案区 | 滚一屏，或点顶栏 | 点左栏或按方向键 | 要滚过 5 屏，或点顶部导航 |
| 最好的地方 | 零学习成本，内容能无限加 | 切到方案时手机缩到右边不消失，点一行手机就跳到对应状态 | 视觉冲击最强 |
| 最大的问题 | 方案和手机不能同屏 | 内容一多就挤；滚轮在第一屏没有反应 | 把面试官的时间花在滚动上 |
| 「过程」的形式 | 泳道 + 下方详情 | 原则列表 + 泳道 | 对话回放 + 窗口条 |

**如果 A 之后还有时间，值得从 B 借一点：** 方案区旁边放一对小手机，点行就联动，不用跳回第一屏。这要在页面上再放一组手机，骨架里没有做。

## 6. 这轮实测发现的问题（上一轮是推断）

| 问题 | 结果 | 处理 |
|---|---|---|
| `devices.css` 第一条规则 `.device *{display:block;box-sizing:border-box}` | **上一轮没预见到。** 它把屏幕里 WeUI 的 flex 布局全部打散：底部导航竖着排，列表项折行 | 只抽出 iPhone 14 Pro 的规则，把这条收窄到外框零件。文件见 `vendor/devices-iphone14pro.css`，从 50 KB 减到 4.5 KB，保留了 MIT 声明 |
| 屏幕要自己裁切和加 transform | 确认必须加。加上后半屏弹层和遮罩的边界与屏幕完全一致（913–1233） | 已写进 `assets/phone.css` |
| 飞卡放在最外层，用 `getBoundingClientRect` 取坐标 | 确认可行，缩放 1.0 和 0.82 下都对得上 | 已实现 |
| 深色模式 | 确认。系统深色时，不设 `data-weui-theme="light"` 列表背景变成 `rgb(25,25,25)`，设了保持白色 | 三个页面的 `body` 都已设置 |
| WeUI 的全局重置 `*{margin:0;padding:0;outline:0}`、`a{cursor:default}` | **新发现。** 会影响外层页面，键盘焦点框也被去掉了 | 外层重新设了 `:focus-visible` 和 `cursor` |
| 弹层层级 | **新发现。** WeUI 底部导航的层级是 500，会盖住半屏弹层的确认按钮 | 把弹层放到更高一层，实测确认按钮能点到 |
| `weui-toast` | 没用，写了一个定位在屏幕内的简单提示 | 如需 WeUI 原版要再试 |
| 飞行中切换布局 | 实测发现，切章节时卡片会飞到旧位置 | 布局变化时让动画立即结束 |

**内容往哪填：** 手机界面和步骤文字在 `assets/core.js` 的 `SENDER`、`RUNNER`、`STEPS`；过程数据在 `assets/process.js`；方案文字在各 HTML 里。

## 7. 没验证的地方

- **只在 macOS 的 Chrome 上测过。** Windows 的微软雅黑效果、Safari、Firefox、QQ 浏览器都没测。
- **没有真机。** 手机宽度是 Chrome 模拟的，触摸手感没试。
- **测试方式：** 用无头 Chrome 设定窗口尺寸、点击、截图。App 内置浏览器只把本地 HTML 显示成静态快照，用不了。动画只看了中间帧，没有肉眼看连续效果，节奏要本人打开确认。
- **`1366×650` 是估算的**可视高度，不是真机数据。
- **大陆访问：** 仍未实测。这轮所有资源都在仓库内，没有外部请求，但 github.io 本身的风险没变。
- **参考实例：** 表里标了哪些打开看过，哪些只读了文字。
- **三个方向都是占位内容。** 标题、费用、地点都是示例；产品名「顺手帮」、信任优先、代占座规则都还等本人确认。

**调研用量：** 搜索 3 次；网页读取 7 次（其中 1 次 404，没有计入参考）。都在上限内。
