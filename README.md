# 校园跑腿互助平台

**在线作品：https://lijiajie-git.github.io/campus-errand/**

打开后先是审题，然后自动播放演示，全程约 1 分 30 秒。播完或点“结束演示”后，产品方案、多窗口 AI 协作和 PRD 才出现。

## 一句话

外卖有人兜底，快递代取丢了没人管，平台把这个责任接过来。

## 解决什么问题

| 痛点 | 解法 | 怎么做 |
|---|---|---|
| 代取快递：丢失追责问题 | 代取闭环 | 本校实名、分段留证、限额内平台先赔再追偿，贵重件可自愿买保险 |
| 接单跑腿：单价太低 | 抢一批 | 同一驿站、同一区域的件打包，少跑很多趟；信用决定能抢多大的批 |
| 广场发单：有隐私隐患 | AI 解析和自动打码 | 截图解析成清单，大厅只露脱敏信息，取件码抢到后才看得到 |

## 范围

- **做：** 快递代取全流程、丢件索赔、下单买保险、订单聊天、圈子。
- **不做：** 代考、代打卡；代占座改成代排队。
- **只写方案：** 外卖派单、代搬运等拓展场景。

完整范围见 [方案/展示清单.md](方案/展示清单.md)。

## 多窗口 AI 协作，做的过程自动出汇报材料

前期把调研等内容同步好，提前想清楚要统计哪些维度（判断、窗口和分工、指令和结果、时间、可展示素材）；执行时由主窗口按 CLAUDE.md 的规则每轮记下来；到汇报时，做了什么、做了哪些判断，都已经沉淀好了。

用 Claude Code 多窗口协作，主要模型是 Claude Opus 5.5，子任务用 Sonnet 5.5。本人实际操作约 2 到 2.5 小时（取本人发消息的时间，间隔超过 10 到 15 分钟算离开）。提交记录的跨度更长，因为中间有离开和过夜，窗口也会继续运行。

全过程记录在 [CLAUDE.md](CLAUDE.md)：工作规则、判断记录（分清本人定的和 Claude 提议的）、交互记录。

## 需要说明的

- 这是产品原型：没有后端和真实支付，AI 解析和打码是演示动画。
- 价格、赔付限额、保险险种、信用门槛都是假设，产品名“顺手帮”是暂定名。
- 调研证据多来自校园外卖，同学互助的一手材料较少。竞品只看了两个校园跑腿小程序的 14 张截图，所以只说“我们看的产品里没看到”。
- 真实截图含个人信息，只留在本地，没有放进这个仓库。
